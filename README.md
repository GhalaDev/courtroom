# المحكمة | THE COURTROOM

لعبة اجتماعية للمحاكمات الخيالية: أدوار سرية، أدلة، استجواب شهود، اعتراضات، كشف تناقضات، تصويت سري، ثم كشف الحقيقة الكاملة.

- **6 قضايا كاملة**، وكل قضية فيها ملفات سرية لكل دور، أدلة عامة وخاصة، شهادات، تناقضات مقصودة، أحداث مفاجئة، وحقيقة واحدة محددة.
- **من 4 إلى 16 لاعبًا**.
- **نمطان للعب**: جهاز واحد (Party Mode) أو أجهزة متعددة عبر غرفة برمز (Online Mode).
- عربي أولًا مع واجهة إنجليزية كاملة (محتوى القضايا بالعربية).

---

## التشغيل على جهازك

تحتاج Node.js الإصدار 22.5 أو أحدث، ولا تحتاج تثبيت أي مكتبات.

```bash
npm start
```

ثم افتح: `http://localhost:3000`

- لتجربة الأجهزة المتعددة على نفس شبكة الواي فاي: افتح من الأجهزة الأخرى `http://<عنوان-جهازك>:3000`.
- لتغيير المنفذ: `PORT=8080 npm start`.
- قاعدة البيانات تُحفظ تلقائيًا في `data/courtroom.db` (SQLite). لتغيير مكانها: `DB_PATH=/path/courtroom.db npm start`.

## الاستضافة على الإنترنت

### الأجهزة المتعددة (يحتاج خادم Node)
**Render** (مجاني): ارفع المجلد على GitHub، ثم في Render اختر *New → Blueprint* وحدد المستودع؛ الملف `render.yaml` جاهز. أو *New → Web Service* مع أمر التشغيل `npm start`.

أي استضافة تدعم Node أو Docker تعمل أيضًا (Railway، Fly.io، VPS). الملف `Dockerfile` جاهز.

> ملاحظة: في الخطة المجانية لبعض الاستضافات يُمسح القرص عند إعادة التشغيل، فتضيع الغرف المحفوظة. للعب في جلسة واحدة لا يؤثر ذلك، وللحفظ الدائم أضف قرصًا دائمًا واضبط `DB_PATH` عليه.

### جهاز واحد فقط (استضافة ثابتة)
مجلد `public` وحده يعمل على Netlify أو GitHub Pages (الملف `netlify.toml` جاهز). في هذه الحالة يظهر زر «أجهزة متعددة» معطلًا مع توضيح، لأن الأجهزة المتعددة تحتاج الخادم.

## كيف تُلعب

1. اختاروا النمط وعدد اللاعبين ثم القضية.
2. يوزّع النظام الأدوار عشوائيًا:
   - 4 لاعبين: القاضي، المدعي العام، محامي الدفاع، المتهم (القاضي يصدر الحكم).
   - 5–6: إضافة شاهد أو شاهدين.
   - 7–9: إضافة هيئة محلفين (1–3).
   - 10 فأكثر: ثلاثة شهود ومحلفون أكثر، ومن 12 لاعبًا: مساعد للادعاء ومساعد للدفاع.
   - الشهود غير المسندين للاعبين يحضرون كشهود افتراضيين بإفادة مكتوبة وأسئلة جاهزة، وبعض الأسئلة تُفتح فقط بعد عرض دليل معين (مواجهة الشاهد بالدليل).
   - يمكن تعديل عدد الشهود والمساعدين من إعدادات الجلسة.
3. كل لاعب يقرأ ملفه السري: ما يعرفه، ما يخفيه، أهدافه، وأحيانًا معلومات يستطيع «كشفها» أمام المحكمة في الوقت الذي يختاره.
4. المراحل العشر: افتتاح القضية ← توزيع الأدوار ← البيانات الافتتاحية ← عرض الأدلة ← استجواب الشهود ← الاستجواب المضاد ← المرافعات الختامية ← تصويت المحلفين ← الحكم ← كشف الحقيقة.
5. الحديث يكون بأصواتكم. القاضي يمنح الكلمة بمؤقت، يعرض أدلة المحكمة، يستدعي الشهود ويصرفهم، ويفصل في الاعتراضات.
6. **الاعتراض**: يضغط المحامي «اعتراض!» ويختار السبب، فيتوقف المؤقت، ويقرر القاضي «قبول» أو «رفض»، وتظهر النتيجة للجميع.
7. **كشف التناقض**: يختار المحامي عنصرين من محضر الجلسة (دليلين، أو إفادة ودليل). إن كان التناقض حقيقيًا ضمن ملف القضية يُعلن للجميع، وإن لم يكن يخسر محاولة.
8. **الأحداث المفاجئة** مرتبطة بكل قضية ومرحلة: دليل جديد، شاهد مفاجئ، رسالة سرية لدور محدد، والفرصة الأخيرة التي يمنحها القاضي.
9. يصوّت المحلفون سرًا (مرة واحدة لكل شخص)، ويختار كل محلف دليلين أقنعاه، ويقيّم عدالة القاضي.
10. بعد الحكم تُكشف الحقيقة: ما حدث فعلًا، الجدول الزمني الحقيقي، الأدلة الحاسمة ومن عرضها، التناقضات المكشوفة والفائتة، الأدلة المضللة وتفسيرها، أسرار كل شخصية، ونقاط كل لاعب.

### نظام النقاط (يمكن إيقافه)
- **المحامون والمساعدون**: عرض دليل حاسم +2، كشف تناقض حقيقي +3، اعتراض مقبول +1 (حتى 3)، وإذا كان موقف فريقك هو الحقيقة واقترب الحكم منها +4 أو +2. المدعي يكسب نقاطًا من كشف الحقيقة حتى لو أضعفت قضيته.
- **المحلفون**: الحكم الصحيح +3 (القريب +1)، و+1 لكل دليل حاسم استندوا إليه.
- **القاضي**: متوسط تقييم العدالة من المحلفين، +2 إن كان وقت الطرفين متوازنًا، +1 للفصل في الاعتراضات، وخصم عند تجاوز المراحل دون استيفاء شروطها.
- **المتهم والشهود**: نقاط مرتبطة بأهداف الشخصية في ملفها (مثل الاعتراف بالحقيقة عندما يُكشف التناقض)، لا بنجاح الكذب.

## البنية التقنية

```
server/server.js     خادم Node بلا مكتبات خارجية: REST + Server-Sent Events للاتصال اللحظي
server/store.js      حفظ الغرف في SQLite (node:sqlite) مع بديل JSON
public/shared/       محرك اللعبة المشترك + القضايا (يعمل في المتصفح وفي الخادم)
  constants.js       المراحل، الأدوار، أسباب الاعتراض، توزيع الأدوار
  engine.js          آلة الحالة: الإجراءات، الشروط، الأحداث، الحكم، النقاط، وviewFor
  cases/             ملف لكل قضية + index.js
public/js/           الواجهة (app.js، views-home.js، views-game.js، net.js، sfx.js، art.js، i18n.js)
```

- **الخادم هو المرجع** في الأجهزة المتعددة: يحفظ الحالة الكاملة، ويرسل لكل لاعب `viewFor(state, playerId)` فقط. الملفات السرية والأدلة الخاصة والحقيقة لا تُرسل لغير صاحبها، والحقيقة لا تُرسل لأحد قبل مرحلة كشف الحقيقة.
- المستعرض في الأجهزة المتعددة لا يحمّل ملفات القضايا أصلًا؛ يأخذ قائمة القضايا من `/api/catalog`.
- كل لاعب له رمز دخول سري يُحفظ في متصفحه؛ تحديث الصفحة أو انقطاع الاتصال يعيده تلقائيًا لنفس الغرفة ونفس الدور.
- الغرف تُحفظ في قاعدة البيانات، فتبقى حتى بعد إعادة تشغيل الخادم (وتنتهي بعد 24 ساعة من الخمول).
- التصويت مرة واحدة لكل محلف، ولا تنتقل المرحلة قبل استيفاء شروطها إلا بزر «تجاوز المرحلة» للقاضي أو صاحب الغرفة (ويُحسب على القاضي).
- لا تسجيل حساب ولا معلومات شخصية: أسماء مستعارة فقط.

**تنبيه صادق**: في وضع الجهاز الواحد تكون القضية كاملة داخل المتصفح بطبيعة الحال، وملفات القضايا موجودة في كود الموقع؛ من يفتح الكود المصدري متعمدًا يستطيع قراءة الحل، مثل من يقرأ كتيّب الحل في لعبة ألغاز. هذا لا يخص الأجهزة المتعددة، حيث لا يرسل الخادم أي سر لغير صاحبه.

### إضافة قضية جديدة
1. انسخ `public/shared/cases/case01-heist.js` إلى ملف جديد وعدّل المحتوى بنفس الشكل: ثلاثة شهود أساسيين + شاهد مفاجئ + المتهم (اختياري على المنصة)، الأدلة (`court` / `prosecution` / `defense` / `event`)، الملفات السرية، الأحداث، التناقضات، الأحكام، والحقيقة.
2. أضفها إلى القائمة في `public/shared/cases/index.js`.
3. لا شيء آخر يحتاج تعديل؛ الواجهة والخادم يقرآن القضية تلقائيًا.
